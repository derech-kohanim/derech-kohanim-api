# דרך כהנים - שרת (API)

צד השרת המשותף לאתר ולאפליקציית האנדרואיד. מחשב מסלולי נסיעה שנמנעים מאזורים האסורים
לכהנים, מאמת כל גיאומטריה מול הפוליגונים בשרת, ומספק חיפוש מקומות, ניהול משתמשים,
הנחיות קוליות וסשני ניווט חי.

בנוי על NestJS ו-TypeScript, מול Postgres עם PostGIS. הנתונים היחסיים מנוהלים ב-Prisma,
גיאומטריית האזורים ב-SQL גולמי כי Prisma אינה יודעת לתאר טיפוסי PostGIS.

---

## הרצה מהירה

```bash
cp .env.example .env      # ואז למלא מפתחות אם יש
npm install
docker compose up -d db   # רק Postgres עם PostGIS
npm run dev               # Nest במצב watch
```

השרת עולה על <http://localhost:3000>, התיעוד על <http://localhost:3000/api/docs>.

בעלייה השרת מריץ **מיגרציות אוטומטית** ואז זורע נתוני הדגמה, כך שאחרי `docker compose up -d db`
אין שום צעד נוסף. אפשר לכבות זאת עם `RUN_MIGRATIONS_ON_BOOT=false` ו-`SEED_ON_BOOT=false`.

### פקודות

| פקודה | מה היא עושה |
|--------|--------------|
| `npm run dev` | Nest במצב watch, מהדר מחדש בכל שמירה |
| `npm run build` | בנייה ל-`dist/` |
| `npm start` | הרצת הבנייה |
| `npm run typecheck` | בדיקת טיפוסים בלבד |
| `npm run seed` | מסמך תנאים, משתמש הדגמה וקטעי קול (לא אזורים). מריץ מ-`dist` |
| `npm run import:areas -- <path>` | ייבוא נתוני האזורים והאזורים המסוכנים. מריץ מ-`dist` |
| `npm run seed:dev` / `npm run import:areas:dev` | אותו דבר דרך `tsx`, לפיתוח ללא בנייה |
| `npm run verify` (זהה ל-`npm test`) | מארז בדיקות ההימנעות ההלכתי, לכל מנוע זמין |
| `npm run prisma:generate` | ייצור מחדש של Prisma Client |

### מסד נתונים בלבד מול מחסנית מלאה

```bash
docker compose up -d db                  # לפיתוח - רק Postgres
docker compose --profile full up --build # מחסנית מלאה, כולל השרת בקונטיינר
```

הפרופיל `full` נועד לשלב מאוחר יותר. בפיתוח יומיומי עדיף להריץ את השרת מ-`npm run dev`,
כדי לראות שינויים מיד ולא אחרי בנייה של דוקר.

> הקשר הבנייה של תמונת הדוקר הוא **תיקיית האב** של הפרויקט, מפני שחוזה הטיפוסים המשותף
> (`derech-kohanim-shared`) יושב במאגר אחות. זה מוגדר כבר ב-`docker-compose.yml`.

### כניסת פיתוח ללא Google

`AUTH_DEV_LOGIN_ENABLED=true` מפעיל את `POST /api/auth/dev-login`, שמחזיר טוקנים למשתמש
ההדגמה בלי שום אישור. זה מאפשר לאתר לעבוד לפני שיש מפתחות Google. חייב להישאר `false`
בכל סביבה שאינה מחשב פיתוח.

משתמש ההדגמה שנזרע:

```
demo@derech-kohanim.local / derech1234
```

## נקודות הקצה

כל התשובות הן JSON. שגיאה מוחזרת תמיד במבנה `{ code, message, details? }`, כאשר `code`
הוא מפתח יציב שהלקוח מתרגם ו-`message` מיועד ללוגים בלבד. השרת לעולם אינו מחזיר טקסט
מוכן להצגה למשתמש.

### בריאות וספקים

| שיטה | נתיב | תיאור |
|------|------|--------|
| GET | `/api/health` | חיות, זמינות מסד הנתונים, מנוע הניתוב האפקטיבי |
| GET | `/api/providers` | רשימת מנועי הניתוב, זמינות, ברירת מחדל ויכולות כל אחד |
| GET | `/api/docs` | תיעוד OpenAPI (גם `/api/docs/json`) |

מנוע ללא מפתח מוצג ברשימה אך מסומן `available: false`. בקשה למנוע כזה נדחית במפורש
(`engine_not_configured`) ולעולם אינה מוחלפת בשקט במנוע אחר.

### אימות

| שיטה | נתיב | תיאור |
|------|------|--------|
| GET | `/api/auth/terms?language=he` | מסמך התנאים הנוכחי והגרסה שיש לאשר |
| POST | `/api/auth/register` | הרשמה במייל וסיסמה, מחייבת `acceptedTermsVersion` תואם |
| POST | `/api/auth/login` | התחברות במייל וסיסמה |
| POST | `/api/auth/google` | אימות `idToken` של Google בצד השרת והחלפתו בטוקנים שלנו |
| POST | `/api/auth/dev-login` | קיצור פיתוח, מאחורי דגל סביבה |
| POST | `/api/auth/refresh` | סבב טוקן רענון. טוקן רענון הוא חד פעמי |
| POST | `/api/auth/logout` | ביטול טוקן רענון |
| GET | `/api/auth/me` | המשתמש המחובר |
| POST | `/api/auth/accept-terms` | רישום אישור של גרסת תנאים חדשה |

סיסמאות מגובבות ב-argon2. טוקני הרענון נשמרים מגובבים, כך שהעתק של מסד הנתונים אינו
מחלק סשנים.

### משתמשים

| שיטה | נתיב | תיאור |
|------|------|--------|
| GET | `/api/users/me` | פרופיל |
| PATCH | `/api/users/me` | עדכון שם תצוגה |
| GET | `/api/users/me/preferences` | שפה, ערכת נושא, רמת חומרה, תנועה, הימנעות מאגרה, קול |
| PATCH | `/api/users/me/preferences` | עדכון חלקי של ההעדפות |

ההעדפות כוללות `avoidTolls` (ברירת מחדל `false`) ו-`avoidDangerZones` (ברירת מחדל `true`),
שמסתנכרנים בין המכשירים. שורות שנכתבו לפני
שהשדה נוסף מקבלות `false` כברירת מחדל ולא נכשלות, כי ההעדפות נשמרות כ-JSON.

### מקומות

| שיטה | נתיב | תיאור |
|------|------|--------|
| GET | `/api/places/search` | השלמה אוטומטית ליעד |
| GET | `/api/places/details` | פתרון הצעה שהגיעה בלי קואורדינטות |
| GET | `/api/places/geocode/stats` | כמה המטמון באמת חוסך |
| GET/POST | `/api/places/saved` | מקומות שמורים |
| PATCH/DELETE | `/api/places/saved/:id` | עדכון ומחיקה |
| GET/POST | `/api/places/recent` | מקומות אחרונים |
| DELETE | `/api/places/recent/:id` | מחיקת מקום אחרון |

`GET /api/places/search` הוא לב המוצר בשלב התכנון, ולכן הסדר בו מכוון:

1. **סיווג בשרת.** קלט כמו `32.0873, 34.8288` מזוהה כקואורדינטות ונפתר מקומית,
   `kind: "coordinates"`, בלי שום קריאה לספק חיצוני
2. **המקומות של המשתמש קודם.** שמורים ואחרונים מוחזרים לפני כל תוצאה חיצונית
3. **ואז תוצאות חיצוניות**: נקודות עניין בשם מ-Places API (New) יחד עם כתובות מגיאוקודינג,
   ממוזגות ומנוקות מכפילויות (לפי `place_id`, ואז לפי קרבה ושם). מקום עניין בשם מדורג לפני
   הכתובת של אותה נקודה. כל שכבה עם מטמון: זיכרון התהליך ואז טבלה במסד. `cached: true` מציין
   שלא בוצעה קריאה חיצונית כלל
4. כל הצעה נושאת `matchedRanges` לצורך הדגשת הטקסט שהותאם, `category`
   (`synagogue`/`poi`/`address`/`city`/...), ו-`distanceMeters` כאשר נשלחה נקודת `lat` ו-`lng`

פרמטרים: `query`, `language`, `lat`, `lng`, `limit`, `sessionToken`.

מזהי ההצעות הם `coord:<lat>,<lng>`, `saved:<id>`, `recent:<id>`, `place:<placeId>` (Places)
או `geo:<placeId>` (גיאוקודינג). `GET /api/places/details` פותר כל אחד מהם.

**נפילה חיננית ומדידה:** `GET /api/places/geocode/stats` מחזיר `available` (גיאוקודינג)
ו-`placesAvailable` (Places API). בלי מפתח, או כשה-Places API אינו מופעל בפרויקט, החיפוש
עדיין עובד ומחזיר קואורדינטות, שמורים, אחרונים וכתובות מגיאוקודינג, פשוט בלי נקודות עניין
בשם. שלוש ה-APIs של גוגל נפרדות וכל אחת חייבת להיות מופעלת בנפרד בפרויקט: **Geocoding API**,
**Places API (New)**, ו-**Routes API**. שגיאת הרשאה מ-Places מדווחת כלשונה בלוג עם הקישור
להפעלה, והשירות מנסה שוב מעצמו כמה דקות אחרי ההפעלה בלי צורך בהפעלה מחדש של השרת.

### אזורים ואזורים מסוכנים

| שיטה | נתיב | תיאור |
|------|------|--------|
| GET | `/api/zones?stringency=basic&sinceVersion=N` | שכבות הפוליגונים ההלכתיות |
| GET | `/api/danger-zones?sinceVersion=N` | אזורים מסוכנים (Area A), ציר נפרד |

שכבות החומרה מצטברות: `taharat` כוללת את `basic`, ו-`machmirim` כוללת את שתיהן. כל פוליגון
נושא `name`, `city`, `street` ואת ה-`description` ההלכתי המלא. התשובה נושאת `version`, וכאשר
`sinceVersion` שווה או גדול ממנה מוחזר `304`.

**האזורים המסוכנים** (Oslo "Area A") הם ציר נפרד מרמת החומרה, בטבלה משלהם עם גרסה משלהם.
`GET /api/danger-zones` מחזיר אותם עם `name`, `city` ו-`description`. הם נמנעים בניתוב כברירת
מחדל (ראה `avoidDangerZones` להלן).

#### ייבוא נתוני האזורים

הנתונים האמיתיים מיובאים בפקודה אחת שמאפסת וטוענת:

```bash
# ייצור, בתוך תמונת הדוקר (מריץ JS מקומפל מ-dist, ללא tsx או קוד מקור):
docker compose exec api npm run import:areas -- /data/areas.json

# פיתוח, ללא בנייה מוקדמת:
npm run import:areas:dev                    # ברירת מחדל: ../derech-kohanim-data/areas.json
npm run import:areas:dev -- <path>          # נתיב מפורש
```

בייצור, `npm run import:areas` ו-`npm run seed` מריצים `node dist/...`. הסקריפטים מקומפלים
לתוך `dist` בזמן `nest build`, וכל הייבוא מ-`@shared` הוא `import type` בלבד ולכן נמחק
בקימפול, כך שאין תלות בזמן ריצה בקוד המקור, ב-tsx או בפתרון נתיבי tsconfig. בפיתוח משתמשים
בגרסאות ה-`:dev` שמריצות דרך `tsx` ללא בנייה. בדוקר ה-compose של הפריסה מרכיב את מאגר הנתונים
לקריאה בלבד תחת `/data`.

הפקודה מסירה את ה-BOM, מנקה את הטבלאות `zones` ו-`danger_zones`, וטוענת מחדש: רמה `א` ->
`basic`, `ב` -> `taharat`, `ג` -> `machmirim` לתוך `zones`, ורמה `A` -> `danger_zones`.
הגיאומטריה מאומתת (טבעות פתוחות נסגרות, פוליגונים פסולים מדולגים ומדווחים). הגרסאות הן גיבוב
תוכן, כך שהרצה חוזרת על אותם נתונים נותנת אותה תוצאה. מודפס סיכום עם מספרי הפוליגונים לכל שכבה.

**אזורי הדגמה אינם נזרעים יותר בעלייה.** מסד נתונים טרי מכיל רק את הנתונים המיובאים; ריצת
`npm run seed` או עלייה טרייה אינה יוצרת אזורי בני ברק להדגמה. מארז הבדיקות מחזיק פוליגוני
בדיקה עצמאיים משלו ואינו נשען על נתונים במסד.

### ניתוב

| שיטה | נתיב | תיאור |
|------|------|--------|
| POST | `/api/routes/compute` | חישוב מסלול |

הגוף כולל `origin`, `destination`, `stringency`, `mode`, `trafficAware`, `language`,
`engine` אופציונלי, וכן `avoidTolls`, `avoidDangerZones` ו-`includeUnavoided`. התשובה היא
`RoutePlan`:

```
RoutePlan {
  routes: RouteResult[]       עד שלוש חלופות מאומתות, הטובה ראשונה, כל אחת עם label
  unavoidedRoute?: RouteResult   המסלול הרגיל ללא הימנעות, להשוואה בלבד
}
```

- **עד שלוש חלופות.** נלקחות מהחלופות המובנות של הספק (HERE `alternatives`, Google
  `computeAlternativeRoutes`), כל אחת מאומתת בנפרד מול האזורים, הנקיות נשמרות, כפילויות קרובות
  מסוננות, והתוצאה מתויגת `fastest` / `shortest` / `alt`. לכל חלופה `id` משלה, וסשן ניווט בוחר
  אחת לפי `id`. אם יש רק חלופה נקייה אחת או שתיים, מוחזרות אלו, ולעולם לא מרפדים בחלופה לא נקייה
- **הימנעות מכבישי אגרה.** `avoidTolls: true` מועבר לספק (HERE `avoid[features]=tollRoad`,
  Google `routeModifiers.avoidTolls`, GraphHopper דרך ה-custom model), ומסומן ב-`avoidsTolls`
  בכל מסלול מוחזר. מרכיב יחד עם הימנעות האזורים והחלופות
- **הימנעות מאזורים מסוכנים.** `avoidDangerZones` (ברירת מחדל `true` כשמושמט) גורם לניתוב
  להימנע גם מפוליגוני האזורים המסוכנים, בנוסף לאזורי החומרה. האימות בשרת מתייחס למסלול הנוגע
  באזור מסוכן כלא נקי. זהו ציר נפרד, וההודעות באזור נושאות `danger`, `description` ו-`city`
- **סינון מרחבי.** מבין מאות אזורים בארץ, רק אלה שבפרוזדור המוצא-יעד יכולים להשפיע על מסלול,
  ולכן הם מסוננים לפי תיבה תוחמת לפני העיבוד. מתכנן העקיפה מקבל תת-קבוצה מצומצמת שכל אזור בה
  מוחלף בתיבה התוחמת שלו (פוליגונים אמיתיים מגיעים לאלפי קודקודים), אך האימות הסופי תמיד מול
  הפוליגון האמיתי, כך שהסינון אינו פוגע בבטיחות
- **המסלול הלא נמנע להשוואה.** כאשר `includeUnavoided: true` וההימנעות באמת שינתה את התוצאה
  (המסלול הרגיל חוצה אזור), מוחזר `unavoidedRoute`: המסלול הרגיל ללא הימנעות, תמיד
  `verifiedClean: false`, לתצוגה בלבד ולא לניווט

כל `RouteResult` נושא מזהה יציב, גיאומטריה, רשימת הנחיות, `verifiedClean`, `reason`,
`detourRatio`, `attribution`, `engine`, `requiredVoiceKeys`, ואופציונלית `avoidsTolls` ו-`label`.
כל הנחיה נושאת `action` יציב (למשל `turn_right`), `distanceMeters` מההנחיה הקודמת,
`geometryIndex`, `street` ו-`voiceKeys`. אזהרות אזור מוזרקות לרשימת ההנחיות כ-`zone_enter`,
`zone_exit`, `zone_origin` ו-`zone_destination`, במקום המדויק שבו הן קורות.

**כל גיאומטריה מאומתת בשרת** מול הפוליגונים, גם כשהספק הצהיר שהוא נמנע. מסלול עם
`verifiedClean: false` מוחזר לצורך הצגה ואבחון בלבד, ואי אפשר לפתוח ממנו סשן ניווט.

#### מה כל מנוע מבטיח

הבדל היסוד, שנמדד ב-POC: רק מנוע שחוסם פוליגונים בתוך חיפוש הגרף יכול לתת ערובה. מנוע
חיצוני שמקבל נקודות ביניים בלבד יכול לשפר סיכויים אך לא להבטיח. פירוט מלא במסמך
`derech-kohanim-poc/docs/google-avoidance.md`.

| מנוע | הימנעות | תנועה חיה | מה הוא נותן |
|------|----------|-----------|-------------|
| `hybrid` | צורה ממנוע חוסם | כן, מגוגל | **ברירת המחדל**. ערובת הצורה, זמן תמיד מגוגל |
| `here` | מובנית, `avoid[areas]` | כן | **ערובה** (בכפוף לאימות השרת) |
| `graphhopper` | מובנית, `custom_model` | לא | **ערובה**, ניתן להרצה עצמאית ללא עלות לקריאה |
| `google` | אין, היוריסטיקה בלבד | כן | **מיטב מאמץ**, לא כשיר כמנוע ראשי |
| `mock` | אין, היוריסטיקה בלבד | לא | לפיתוח לא מקוון בלבד |

לגוגל ולמוק, השרת מפעיל את מתכנן העקיפה שהוכח ב-POC: גרף נראות סביב הפוליגונים, טבעת
מועמדים, סבבים אדפטיביים, ובחירת התוצאה הנקייה **הקצרה ביותר**. בנוסף, לגוגל מבוקשות
חלופות באותה קריאה ונבחרת מהן הנקייה (המלצה 4.3 של מסמך ה-POC) - שיפור זול שמצמצם את
מספר סבבי העקיפה.

`detourRatio` מוחזר בראש התשובה, כך שעקיפה יקרה גלויה. יחס גבוה = הימנעות מאריכה.

#### המנוע המשולב וזמני הנסיעה (§6.7)

לפי החלטת המוצר, **זמן הנסיעה והתנועה מגיעים תמיד מגוגל**, בשני המצבים, מתומחרים על גבי
הצורה שקבע מנוע חוסם פוליגונים. זהו המנוע `hybrid` (ברירת המחדל, `HYBRID_SHAPE_ENGINE=here`).

- הצורה המוצגת והמנווטת היא **תמיד** של מנוע הצורה, מאומתת נקייה. גוגל רק עונה "כמה זמן
  לוקח הפרוזדור הזה", ואף פעם אינו קובע את הצורה.
- `trafficAware=false` -> גוגל ב-`TRAFFIC_UNAWARE` (זרימה חופשית). `trafficAware=true` ->
  גוגל ב-`TRAFFIC_AWARE` (תנועה חיה). שני הזמנים שונים כשהתנועה שונה.
- כדי שגוגל יעקוב אחרי הצורה, היא נדגמת לנקודות מעבר **לפי מרחק**, בערך אחת לקילומטר (עד
  התקרה של 25 נקודות בגוגל). צפיפות יתר דווקא מזיקה: נמדד שכפיית 25 נקודות בפרוזדור שגוגל
  חולק עליו שילשה את המרחק, בעוד נקודה לקילומטר נותנת לו לעקוב על כבישים אמיתיים.
- שער הסטייה **אינו בדיקת דיוק** אלא גלאי "מסלול אחר". זמן הוא הערכת הגעה, לא תכונת בטיחות
  (תכונת הבטיחות היא הגיאומטריה הנקייה, שתמיד של מנוע הצורה ותמיד מאומתת). לכן הזמן של גוגל
  מתקבל גם על תנודת הצמדה וגם על פרוזדור שגוגל מתפתל לאורכו, ונדחה רק על אי-התאמה גסה: סטייה
  מעל כמה מאות מטרים ביחס לאורך, או מרחק כולל החורג ביותר מ-60% מהצורה. רק אז נופלים חזרה
  לזמן של מנוע הצורה, עם הערה מפורשת ביומן.
- מסלול שעדיין נוגע באזור אינו מתומחר כלל (אין לבזבז קריאה על מסלול שייפסל), והאימות מול
  הפוליגונים מתבצע בסוף כרגיל.

`npm run verify` מאמת לשני המסלולים ששני מצבי התנועה מתומחרים על ידי גוגל, שהזמנים שונים,
ושהגיאומטריה נשארת של מנוע הצורה ומאומתת.

מארז `npm run verify` בודק לכל מנוע זמין: הימנעות דולקת אינה חוצה אף אזור, הימנעות כבויה
כן חוצה (כדי שהנתונים יהיו משמעותיים), ונקודת קצה בתוך אזור נכשלת בבטחה. המנוע `mock`
לא מקוון ודטרמיניסטי, ולכן הוא החלק המובטח של הריצה, מנועים אמיתיים נבדקים כשיש מפתח
ושגיאת רשת מדווחת כ-SKIP ולא כ-FAIL.

### אירועים ודיווחים על מסלול

| שיטה | נתיב | תיאור |
|------|------|--------|
| GET | `/api/routes/:id/events` | פיד האירועים של מסלול |
| POST | `/api/routes/:id/reports` | דיווח נהג על מסלול (מחייב התחברות) |

כל מסלול שחושב נשמר לפי המזהה היציב שלו (גיאומטריה, הנחיות ומוצא), ולכן אפשר לבקש את
פיד האירועים שלו. `GET /api/routes/:id/events` מחזיר `RouteEventBundle`:

- **אירועי אזור** נגזרים מהנחיות ה-`zone_enter` של המסלול עצמו, עם המיקום, המרחק לאורך
  המסלול, ושם האזור בעברית ובאנגלית
- **תנועה בזרע**: מקטע עומס כבד ומקטע בינוני על טווחי אינדקסים בגיאומטריה, אירוע `traffic`
  בנקודת הפקק, ו-`delaySeconds` המחושב מאורך הקטע הכבד. הפיד דטרמיניסטי לכל מסלול, כך
  שאותו מסלול תמיד מחזיר אותו פיד
- **דיווחי משתמשים** שהוגשו למסלול הזה

הפיד תואם במדויק את מימוש ההדגמה בצד הלקוח (`mockEventsForRoute`), כדי שהלקוח יוכל לוותר
על ההעתק המקומי שלו. מסלול לא מוכר או שפג מחזיר `404` עם קוד `route_not_found`.

`POST /api/routes/:id/reports` מקבל `type` ו-`location`, שומר את הדיווח מיוחס למשתמש
המחובר, ומחזיר את ה-`RouteEvent` שנוצר עם `reportedByUser: true` ו-`createdAt`. הדיווח
מופיע בפיד האירועים של אותו מסלול מכאן ואילך.

### הנחיות קוליות

| שיטה | נתיב | תיאור |
|------|------|--------|
| GET | `/api/voice/packs` | רשימת החבילות, או מניפסט לפי `language` ו-`voice` |
| POST | `/api/voice/clips/resolve` | קבלת המקטעים שהמסלול דורש |
| GET | `/api/voice/clips/:id` | הורדת מקטע |

הנחיה קולית מורכבת ממקטעים קצרים ולא ממשפט מוכן. מפתח מקטע הוא `<תפקיד>.<ערך>`, למשל
`prefix.in`, `dist.200m`, `action.turn_right`, `zone.enter`. המרחקים המוכרזים הם סולם
סגור, כך שספריית הקבצים נשארת קטנה.

שמות רחובות הם אוצר מילים פתוח ולכן מפתח המקטע שלהם הוא גיבוב של השם, `street.<hash>`.

**ייצור הדיבור ממומש מול Google Cloud Text-to-Speech**, מאחורי ממשק `TtsService`. ב-resolve,
כל מפתח מהקטלוג הסגור שאין לו עדיין שמע מיוצר, נשמר במסד עם `source=generated`, וגרסת החבילה
מקודמת. `GET /api/voice/clips/:id` מגיש את השמע עם ה-`Content-Type` הנכון. מפתח שכבר יש לו
שמע מוגש מהמסד ואינו מיוצר שוב.

- מפתח שאי אפשר לייצר (שירות לא זמין, או שם רחוב שאין לנו את הטקסט שלו מהמפתח בלבד) חוזר
  ב-`missing`, והלקוח מקצר את ההנחיה. **הניווט לעולם אינו ממתין לשמע.**
- הבחירה נעשית ב-`TTS_PROVIDER`: `google` (ברירת מחדל) או `offline`. המצב `offline` הוא
  מחולל צליל סינתטי לפיתוח ולאימות צינור השמירה וההגשה בלי API בתשלום ומופעל. הוא אינו דיבור
  אמיתי ומיועד לשימוש מקומי בלבד.
- דרוש להפעיל את Text-to-Speech API בפרויקט של המפתח. שגיאת הרשאה כאן משמעה לרוב שהשירות לא
  הופעל, לא שהמפתח שגוי (לקח 16.4 של ה-POC), ולכן היא מדווחת כלשונה בלוג.

ואינו חוסם את המסך.

```
    003_route_reports.sql  דיווחי נהגים על מסלול
    004_voice_clip_audio.sql  בתים ו-content-type למקטעים שנוצרו
    005_places_cache.sql   מטמון קצר לתוצאות Places
    006_zone_data_and_danger.sql  city/street/description ב-zones + טבלת danger_zones

  auth/                  הרשמה, התחברות, Google, JWT, תנאים
  users/                 פרופיל והעדפות
  places/                חיפוש, פרטים, שמורים, אחרונים, גיאוקודינג עם מטמון
  zones/                 שכבות הפוליגונים
  routing/               תזמור ניתוב + חמישה ספקים מאחורי ממשק אחד, presets לבדיקות
  voice/                 חבילות קול, קטלוג מקטעים, Google TTS + מחולל לא מקוון
  navigation/            סשני ניווט חי
  events/                פיד אירועי מסלול ודיווחי נהגים

  seed/                  נתוני זריעה

```

חוזה הטיפוסים מיובא מ-`derech-kohanim-shared` דרך הכינוי `@shared`. הייבוא הוא של
טיפוסים בלבד, ולכן אין לו שום עקבה בזמן ריצה.

### מיגרציות

המיגרציות הן קובצי SQL רגילים שרצים לפי סדר שמות ונרשמים בטבלת `schema_migrations`.
קובץ `001_init.sql` נוצר מסכמת Prisma:

```bash
npm run prisma:diff > prisma/migrations/001_init.sql
```

לאחר שינוי ב-`schema.prisma` יש להוסיף קובץ מיגרציה חדש ולהריץ `npm run prisma:generate`.

## פתרון תקלות

**`docker compose up -d db` נכשל על הפורט.** יש כבר Postgres מקומי על 5432. יש לשנות את
`DB_PORT` בקובץ `.env` ואת `DATABASE_URL` בהתאם.

**רשת שבודקת תעבורה מוצפנת.** בסביבות עם פרוקסי ארגוני, סביבת הריצה אינה מכירה את תעודת
השורש של המיירט וכל קריאה לספק נכשלת בצורה שנראית כמו תקלה אצל הספק. יש להזריק את התעודה
דרך `API_EXTRA_CA_CERTS`. שים לב שהמשתנה בקובץ ההגדרות אינו נקרא `NODE_EXTRA_CA_CERTS`
בכוונה: השם הזה לרוב כבר מוגדר במחשב המארח, וסביבת המארח גוברת על קובץ ההגדרות.

**שגיאת הרשאה מספק ניתוב.** לא בהכרח בעיית מפתח. פעמיים ב-POC מדובר היה בשירות שכלל לא
הופעל בפרויקט. הודעת הספק מועברת ללוג כלשונה בדיוק בשביל זה.

**אין אף מנוע ניתוב מוגדר.** השרת נופל למנוע ההדגמה `mock` כדי שהמחסנית תמיד תעבוד,
ומסמן זאת ב-`/api/health` בשדה `mock: true`. הלקוח אמור להציג באנר אזהרה במצב הזה.
